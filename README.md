# Mini NPU Simulator

Python 3.8 이상에서 동작하며 외부 라이브러리가 필요하지 않습니다.

## 실행 방법

`main.py`와 `data.json`을 같은 폴더에 두고 `python main.py`를 실행합니다.
메뉴 `1`은 3×3 필터 A/B와 패턴을 각각 세 줄씩 입력하는 모드입니다. 한 줄에는 공백으로 구분한 유한한 숫자 세 개를 입력합니다. 오류가 있는 줄은 재입력합니다.
메뉴 `2`는 같은 폴더의 `data.json`을 읽고 각 패턴을 검사합니다. 예제 JSON은 5×5, 13×13, 25×25 케이스 7개(정상 6개, 의도적 동점 1개)입니다. 실제 과제에서 제공된 `data.json`이 있다면 예제 파일을 교체하십시오.

## JSON 구조

최상위 키는 `filters`와 `patterns`입니다. `filters`는 `size_5`, `size_13`, `size_25`를 키로 갖고, 각 크기별로 `cross`와 `x`라는 필터 배열을 담습니다. `patterns`는 `size_N_idx` 키마다 `input`(N×N 숫자 배열)과 `expected`(`+` 또는 `x`)를 담습니다. 필터 키의 `cross`와 expected의 `+`는 `Cross`로, `x`는 `X`로 정규화됩니다. `Cross`/`X` 자체도 허용합니다.

## 구현 요약

`mac`은 이중 반복문에서 패턴과 필터의 같은 좌표 값을 곱해 누적합니다. 두 점수의 차이의 절댓값이 `1e-9`보다 작으면 `UNDECIDED`, 아니면 더 큰 점수의 라벨을 반환합니다. 비교 정책은 절대 허용오차이며 경계 `1e-9`는 동점에 포함되지 않습니다. 입력 데이터의 크기, 자료형, 숫자의 유한성, 라벨 및 필터 존재 여부를 검증합니다. 필터 그룹이 잘못되어도 해당 그룹을 참조하는 패턴은 개별 FAIL로 기록합니다.

## 결과 리포트

1. 제공된 예제 데이터는 총 7개 패턴으로 구성됩니다.
2. 6개는 Cross 또는 X 필터와 동일한 패턴이므로 해당 라벨로 판정되어 PASS가 예상됩니다.
3. `size_13_3`은 모든 원소가 0이어서 두 필터의 MAC 점수가 모두 0입니다.
4. 따라서 `size_13_3`은 `UNDECIDED`로 판정되며 expected `X`와 달라 FAIL이 예상됩니다.
5. 예제의 예상 집계는 전체 7개, PASS 6개, FAIL 1개입니다.
6. 실제 과제의 원본 `data.json`은 제공되지 않았으므로 그 파일에 대한 결과는 별도 실행으로 확인해야 합니다.
7. 라벨 정규화가 없다면 expected `+`와 예측 `Cross`가 다르게 비교되어 잘못된 FAIL이 발생할 수 있습니다.
8. 필터 키 `cross`를 `Cross`로 바꾸는 것도 같은 의미의 라벨을 일관되게 처리하기 위해 필요합니다.
9. 행·열 개수 불일치, 숫자 이외의 값, 누락된 필터, 잘못된 키는 데이터/스키마 문제로 분류합니다.
10. 정상적인 스키마인데 예상과 다른 라벨이 나오면 입력 패턴과 필터 내용, 예상 라벨 및 MAC 판정 로직을 점검합니다.
11. 두 점수가 거의 같은 경우에는 부동소수점 반올림 오차가 판정을 뒤집을 수 있습니다.
12. 절대 허용오차 `epsilon=1e-9`는 이런 작은 차이를 동점으로 처리해 불안정한 판정을 줄입니다.
13. 다만 epsilon으로 인한 `UNDECIDED`는 expected가 Cross 또는 X라면 FAIL이며, 임의로 PASS로 바꾸지 않습니다.
14. 성능 표의 시간은 파일 읽기나 출력이 아닌 MAC 함수 호출만을 10회 측정한 평균입니다.
15. 측정 단위는 ms이며 실행 장치, Python 버전, 운영체제 부하에 따라 달라집니다.
16. MAC의 각 원소에 대해 곱셈 1회와 누적 덧셈 1회가 수행되므로 반복 횟수는 N²입니다.
17. 3×3, 5×5, 13×13, 25×25의 원소별 연산 횟수는 각각 9, 25, 169, 625입니다.
18. 따라서 단일 MAC 함수의 시간 복잡도는 **O(N²)**이며, 추가 누적 변수의 공간 복잡도는 **O(1)**입니다(입력 배열 저장 공간 제외).
19. 두 필터를 평가하면 약 2N²번의 원소별 연산이 필요하지만 상수 배수이므로 전체 시간 복잡도 역시 O(N²)입니다.
20. 작은 입력에서는 함수 호출 및 타이머 오버헤드 때문에 실제 측정 시간이 N²에 정확히 비례하지 않을 수 있습니다.
21. 모든 케이스가 PASS인 데이터에서는 정규화, 스키마 검증, 점수 비교 정책이 주어진 expected와 일치한 것으로 해석할 수 있지만, 프로그램 전체의 무오류를 보증하지는 않습니다.
